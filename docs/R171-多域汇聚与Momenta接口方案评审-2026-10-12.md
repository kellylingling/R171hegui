# R171 多域汇聚与 Momenta 接口方案评审

日期：2026-10-12。输入为用户提供的职责描述与方案图；未取得 Momenta proposal 全文、车型网络拓扑、SDK、Topic 字典或批准机关的具体交付要求。法规分析沿用项目已核对的 R171 01 系列及 Supplement 1；具体车辆按实际批准版本执行。

## 判断

“各域提供所需结构化数据，由 OEM 车端采集服务汇聚，经 TCU 上传 OEM 云”的方向合理，是汽车遥测中常见的集中汇聚架构，可作为总体方案候选。公开材料不足以证明这个具体方案的市场占比，也不足以证明现有车辆平台可直接实现。

当前图表达了传输路径，尚未覆盖 R171 合规闭环。需要增加事件留存、跨域时序与身份关联、数据质量、软件批准映射、事故调查、周期统计和对批准机关的报告与回执。“已经传到 OEM 云”不能作为“已经满足 R171”的验收条件。

## 对输入观点逐项评审

| 观点 | 判断 | 修正或补充 |
|---|---|---|
| 先由 OEM 与海外业务/法规认证团队澄清总体方案，再明确 M 的 Topic 和排期 | 正确 | 批准版本、功能范围、报告机关/通道、数据项与责任方先定；M 可并行开展现有字段盘点和技术预评估，接口冻结后承诺最终范围与周期 |
| M 只负责智驾域部分 | 作为供应商接口分工合理 | M 负责约定的智驾信号语义、源时序、版本、质量和适配；OEM 对整车监测与报告完整性负责。DMS/HMI 的实际部署和权威来源需单独确认，不能凭名称假设一定属于 M |
| 智驾信号通过总线转发至网联域，OEM 整合各域后上云 | 合理 | 建议采用 OEM 控制的逻辑汇聚服务，物理位置可以是网关、中央计算平台或网联域；不要预先强制所有采集都在 TCU 内实现 |
| 非视频结构化数据可直接域间传输 | 有条件成立 | 能传输不代表可无条件直转；还需编码、Schema、带宽、优先级、事件捕获、重启和缺失处理。非视频也可能包括高带宽点云、目标列表等，不能单按“是否视频”决定传输方式 |
| OEM 提供上传 SDK，M 完成信号映射适配 | 可行，但部署表述不清 | 若云上传 SDK 在网联域运行，M 对接的是域间接口和采集 API；若 SDK 部署在智驾域，需明确它只入队还是直接联网、是否持有凭证、资源隔离和责任。云上传 SDK 与域间发送组件是两种接口 |
| SOME/IP 实时转发 | 可选工程方式 | SOME/IP 是车载以太网服务通信机制，不是 R171 规定协议；应用需约定服务/事件 ID、可靠性、序号、订阅恢复和持久化。传输成功或使用 TCP 也不等于掉电后证据可用 |
| OEM 云向政府监管云推送安全事件数据 | 对 R171 描述不准确 | 应为 OEM 调查及报告服务向授予批准的 Type Approval Authority 提交通知、调查结果和周期报；通道与该机关商定。涉及设计整改时再由批准机关向 DETA 交换信息 |

## 如何通过该路径支撑 R171

R171 第 7 段要求厂家建立有效监测和分析程序，并通知、调查和报告。法规不规定统一的 SOME/IP Topic、上传 SDK、政府遥测 API 或全量智驾数据回传方式。

| 输出 | 要做的事 | 该方案中的落点 |
|---|---|---|
| 重大安全事件首报，7.2.1 | 识别适用碰撞后果及功能状态窗口；知悉后无不合理延误，先报当时可得信息 | 车端事件记录 + OEM 事件受理；客服/维修/保险信息补充；批准机关出口 |
| 短期调查报告，7.2.2.1 | 调查事故与 DCAS 是否相关；若很可能为原因之一，提供适用的拟设计整改 | OEM 牵头联合供应商调查，关联事故前后状态、软件、必要测试与附加证据；不是把信号包换个名称上传 |
| 周期报告，7.2.3.1 | 至少每年报告规定指标；重大系统变化区分；更高报告频率按实际监督要求 | 多域统计 + OEM 车辆配备台账 + 版本化计算；01 系列覆盖 Table 1 九项与相关暴露量 |
| 设计整改信息交换 | OEM 提供整改信息，批准机关上传英文材料 | Supplement 1：批准机关收件后最迟 14 天上传 DETA。该期限不属于厂家首报，也不是车端上传 SLA |

重大安全事件不只由气囊报文决定：需医疗援助的伤情可能事后知悉。因此，车端触发采集只是一个入口，仍需客服、维修、保险及主管机关线索渠道。

一般通知范围涉及事故时 On 和事故前 5 秒的条文条件；01 系列对系统发起动作另涉及事故前 7 秒内有关功能 Active。On 包含 Stand-by。要保存状态转变而非只发事故当时一个布尔值。具体窗口判定必须按适用条文及批准机关确认的口径实现。

首报和调查报告不能等同。完整日志、视频或根因结论尚未取得时，不应因此无故延迟首报；后续补充调查进展和结果。统一的 24 小时/7 天厂家期限不能从上述条文推出，企业应明确内部响应时限及升级路径，并满足批准机关的实际要求。

## CFDI 与合规数据的关系

按用户描述，CFDI 回传全量智驾数据；其内部具体用途、协议和覆盖率尚未核实。它与 R171 监测报告具有不同交付目标。

全量智驾数据不等于完整监管证据：可能缺少气囊/约束装置、动力系统关闭、实际 HMI 告警、整车配备台账、伤情以及批准版本等信息。反过来，R171 也不统一要求持续回传所有原始智驾数据。

可复用同一个 TCU、连接和传输框架，但应划分处理目的、数据集、优先级、权限、留存和可用性要求；法规事件元数据不应被大体积研发任务阻塞。可选研发采集配置变化不应让合规监测悄然失效。CFDI 的相关证据如果合法、完整、可关联，可以用于后续调查；两类链路没有必须物理分离或禁止复用的统一 R171 要求。

## 推荐实现及接口边界

路径为：各域权威源 → OEM 车端合规采集与持久记录 → 网联/TCU → OEM 地域云 → 调查、指标、审签与报告 → 型式批准机关；设计整改另经批准机关 → DETA。

### 车端

- 智驾域提供 DCAS 与功能状态、退出原因、系统边界、动作及中止、驾驶员覆盖、软件/标定/模型版本等约定数据。告警应取实际发出的告警状态，不能仅凭 DMS 原始判断推算 HMI 已告警。
- 其他域补充碰撞与约束触发、动力系统状态、车速/里程及实际 DMS/HMI 数据；每个字段指定唯一权威来源。HMI 显示、智驾告警请求与驾驶员实际收到的告警如有差异，需有可追溯定义。
- 源域保存易丢失的瞬态事件和关键前史；OEM 汇聚器进行跨域关联、持久计数与证据包组装。云端可重算，但不能把所有短时窗口仅依赖于有网时的云端计算。
- 建议同时提供“事件消息”和“累计统计快照”，不要只提供降采样后的周期信号或只保留聚合结果。短暂事件可能被周期采样漏掉；纯聚合数据不一定足够解释事故。
- 定义事件关联 ID、源 ECU/功能、源时间戳、单调时钟与 UTC 映射、启动周期 ID、序号、Schema/规则/软件版本、有效性和缺失信息。事件 ID 和时间同步的产生/传播方式由 OEM 统一设计。
- 采样率、最大延迟、缓存时长、队列容量和总线预算根据需求与平台实测确定，都是工程参数，不是 R171 的统一规定。瞬态事件优先事件触发，周期统计使用持久累计值；云端到达时间不能替代源事件时间。

### 网联域与云端

- 网联域负责设备认证、加密、优先队列、断点续传、上传确认和数据质量上报；证据包的本地落盘、掉电行为和故障恢复须有明确所有者。
- 建立事故损坏导致智驾域、总线或 TCU 不可用时的取证降级路径；必要时利用源域缓存及授权本地导出。不假设任意碰撞情况下都能立即上传。
- OEM 云关联车辆、批准、实际软件配置、已采集覆盖率与多域证据；进行事件去重和调查。配备车辆数不能用已联网车辆数替代，失联不能简单当作无事件。
- 事件元数据优先，必要的视频/大文件单独走分片对象上传。最小结构化集合支撑识别与统计，后续根因分析所需的附加证据依据事故和系统设计确定；“非视频即可满足所有调查”没有依据。
- OEM 法规认证团队负责向批准机关报告；海外业务团队协同地域部署、当地运维及数据治理，但不能以其内部确认替代批准机关的交付要求。

### 应冻结的接口表

每个数据项至少包含：法规/报告用途、字段定义、权威源、单位与枚举、状态转换语义、事件触发/周期、源时间与精度、延迟/带宽预算、持久化责任、错误/缺失语义、版本兼容、隐私类别、验收用例。再映射为车辆平台的 Service/Event/Field 或其他总线报文。

“Topic”可能指智驾进程内部消息、SOME/IP 服务事件或云消息主题，不能直接混用。M 提供的是哪一层，谁承担每一层转换，需在接口说明中逐段明确。

## 优缺点与备选方案

| 维度 | 集中汇聚方案的优点 | 代价或风险及措施 |
|---|---|---|
| 职责 | OEM 控制完整整车数据及报告，供应商聚焦自己的域 | OEM 集成及组织协调工作较大，需要法规、整车、网联、云及供应商共同负责接口验收 |
| 云端连接 | 统一身份、传输、地域和权限，减少多域各自连接 | 汇聚/TCU 成为集中故障点；用源域缓存、持久队列、本地导出和丢失检测补足 |
| 跨域语义 | 易统一车辆/事件 ID、时间和报告口径 | 各域采样率、时钟、复位和软件版本不同；保留源时间、质量状态并完成整车回放 |
| 带宽与成本 | 对法规所需信号过滤聚合，降低移动网络流量 | 过滤或降采样过度可能丢掉事件与调查证据；事件消息与累计快照双轨，必要大文件独立上传 |
| 维护 | SDK 和云接口统一管理，多车型可复用 | SDK/API 与服务版本耦合、中央服务资源不足；适配层隔离、兼容矩阵和资源预算 |
| 安全与数据治理 | OEM 统一权限、用途、留存和地域策略 | 更多跨域路径和集中存储；最小字段、传输保护和访问审计，上传不可影响智驾安全任务 |

| 备选架构 | 适用情形 | 取舍 |
|---|---|---|
| 网关/网联集中采集 | 现有车型已有可复用的采集和网联能力 | 建议优先评估，但资源和事故可用性需验证 |
| 中央计算/整车数据服务采集，TCU 仅负责通信 | 已采用中央或区域式电子电气架构 | 保留同样的 OEM 统一治理，避免硬塞入网联域；需要明确中央服务与 TCU 的故障边界 |
| 各域分别直接上云 | 已有独立采集栈、特殊高带宽诊断等 | 域内实施自主，但身份/网络/重传/治理重复，跨域关联与总责任更复杂；不能因此视为不符合 R171 |

以上是工程取舍，不是有统计证据的行业市场份额排名。最终选择取决于目标车型的平台能力、数据预算及监测计划，R171 本身不指定这些拓扑。

## 联合澄清及验收

OEM 与海外业务、法规认证、网联、云团队牵头，Momenta 及其他域供应商参与，输出五项：适用批准与报告通道矩阵、法规到数据映射、多域时序与事件设计、SDK/域间接口说明、端到端责任与验收表。

M 可先评估现有信号覆盖和缺口，再按新增源信号、映射适配、缓存/同步、集成/联调分别估期。目前没有 M 的完整 proposal 和平台实测，不能给出可信的具体周数。

建议验收用例：短于周期采样间隔的告警、相关事故前退出、重复告警窗口及重置、禁用后不足 5 分钟关闭动力系统、断网重传/重复/乱序、任一域重启、碰撞后 TCU 损坏、OTA 跨版本，以及先无气囊报文、后知悉医疗伤情。由已知场景预期检查原始事件、累计统计、调查记录和最终报告，不能只做 Topic 收发成功检查。

## 可用于对齐的表述

“建议由 OEM 牵头总体设计，按实际 R171 批准版本明确监测、报告及证据要求。Momenta 提供约定的智驾域状态、事件和统计接口；OEM 组织其他域、时间关联、事件留存与统一车云上传，并负责 OEM 云的调查、周期报及批准机关交付。结构化数据优先复用域间通信，SDK 部署层级、缓存与错误处理由接口规范确定。CFDI 可复用传输基础设施，但其全量智驾回传不自动构成整车 R171 合规证据。接口范围冻结后，Momenta 评估智驾部分实施周期。”
